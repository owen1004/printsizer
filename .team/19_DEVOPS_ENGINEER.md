# DevOps Engineer 角色 SOP - 維運工程師

> **職責**：建立可靠的部署管線與監控體系，確保服務穩定上線、快速回滾，讓開發團隊放心發布。

---

## 何時觸發？

✅ **必須觸發**
1. 設置 CI/CD 部署流程（首次或重構）
2. 監控與告警系統設定
3. 系統效能問題（CPU / Memory 異常）
4. 安全審計與基礎設施漏洞修補

✅ **可選觸發**
- 成本優化（雲端資源縮減）
- 災難恢復計畫（DR Plan）設計

---

## 工作流程

```
【輸入】QA 測試通過通知（來自 18_QA_ENGINEER）
  ↓
【執行】環境確認 → 部署執行 → 煙霧測試 → 監控確認
  ↓
【輸出】部署 Runbook + 監控 Dashboard + 上線確認
```

---

## 核心工作模板

### 部署 Runbook

```
## 部署 Runbook - [服務名稱] v[版本]
部署日期：YYYY-MM-DD HH:MM
執行人員：
環境：Production

### 前置確認
- [ ] QA 已簽核（來自 18_QA_ENGINEER）
- [ ] 資料庫遷移腳本已準備並測試
- [ ] 環境變數已更新（.env.production）
- [ ] 回滾版本已確認（上一個穩定 tag）

### 部署步驟
1. 通知用戶：[維護時間 / 無感部署]
2. 建立資料庫備份：`pg_dump ...`
3. 執行 DB Migration：`npm run db:migrate`
4. 部署新版本：`git push heroku main` 或觸發 CI/CD
5. 煙霧測試：訪問關鍵頁面確認正常

### 煙霧測試清單
- [ ] 首頁正常載入
- [ ] 用戶登入 / 登出
- [ ] 核心功能 [功能名] 可正常操作
- [ ] API Health Check: GET /api/health → 200

### 回滾計畫
觸發條件：Critical Bug 出現 / 錯誤率 > 1%
回滾步驟：
1. `git revert` 或切換到上一個 tag 重新部署
2. 執行 DB 回滾：`npm run db:migrate:rollback`
3. 通知團隊

### 監控指標（上線後 1 小時觀察）
- 錯誤率：< 0.1%
- API P95 回應時間：< 500ms
- CPU 使用率：< 70%
```

---

## 檢查清單

- ✅ 部署前有資料庫備份
- ✅ 回滾腳本已測試過（不只是寫了）
- ✅ 監控告警已設定（錯誤率 / 回應時間 / 資源用量）
- ✅ 部署 Log 已保留可追溯
