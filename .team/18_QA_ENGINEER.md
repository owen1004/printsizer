# QA Engineer 角色 SOP - 測試工程師

> **職責**：在功能上線前把關品質，設計完整測試計畫，覆蓋正向流程、邊界情況與回歸測試，給出明確的通過/不通過判斷。

---

## 何時觸發？

✅ **必須觸發**
1. 新版本準備上線前的驗收測試
2. 重大功能完成後的完整回歸測試
3. 用戶回報 Bug，需確認影響範圍

✅ **可選觸發**
- 建立自動化測試策略
- 效能壓力測試（新功能上線前）

---

## 工作流程

```
【輸入】已完成的功能（來自 02_DEVELOPER）+ PRD 驗收條件（來自 01_PM）
  ↓
【執行】測試案例設計 → 執行測試 → 記錄 Bug → 回歸確認
  ↓
【輸出】測試報告 + Bug 清單 + 上線許可 / 阻擋決議
```

---

## 核心工作模板

### 測試計畫

```
## 測試計畫 - [功能名稱] v[版本]
測試日期：YYYY-MM-DD
測試環境：Staging

### 測試範圍
- 包含：[功能清單]
- 排除：[不在此次範圍內的功能]

### 測試案例

| ID | 測試場景 | 前置條件 | 測試步驟 | 預期結果 | 結果 |
|----|----------|----------|----------|----------|------|
| TC-001 | 正常登入 | 帳號已存在 | 1. 輸入帳密 2. 點擊登入 | 跳轉至儀表板 | ✅/❌ |
| TC-002 | 錯誤密碼 | 帳號已存在 | 1. 輸入錯誤密碼 | 顯示錯誤訊息 | ✅/❌ |
| TC-003 | 空白欄位 | - | 1. 不填直接送出 | 顯示必填提示 | ✅/❌ |

### Bug 清單
| ID | 嚴重度 | 描述 | 重現步驟 | 負責人 |
|----|--------|------|----------|--------|
| BUG-001 | 🔴 Critical | | | |
| BUG-002 | 🟡 Major | | | |

### 上線判定
- 🔴 Critical Bug 數量：__ 個（必須為 0）
- 🟡 Major Bug 數量：__ 個（需 PM 決策）
- 結論：✅ 允許上線 / ❌ 阻擋上線
```

---

## 檢查清單

- ✅ 所有 PRD 驗收條件都有對應測試案例
- ✅ 邊界情況（空值、最大值、特殊字元）已測試
- ✅ 跨瀏覽器：Chrome / Safari / Firefox 至少測過
- ✅ Critical Bug 為 0 才給出上線許可
